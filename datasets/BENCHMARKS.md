# Program induction benchmarks

These data files preserve the authors' public training and test examples. The adapter in `tasks/benchmarks.py` reads one task instance at a time. No benchmark outputs are generated by a language model.

| `--task_type` | `--benchmark_id` | Source | Oracle |
|---|---|---|---|
| `cryptography` | `caesar:0` through `caesar:99`, `atbash:0` through `atbash:99`, or `keyboard:0` through `keyboard:99` | [Robust Rule Induction](https://github.com/HKUST-KnowComp/Robust-Rule-Induction) | cvc5 symbolic execution of Python string functions on ASCII-letter strings of length 0–10 |
| `list_functions` | `c001` through `c250`, where present in the source file | [Robust Rule Induction](https://github.com/HKUST-KnowComp/Robust-Rule-Induction), derived from Rule's list-function benchmark | cvc5 sequence theory for directly translatable functions, then cvc5 selection over a bounded concrete input pool |
| `instruction_induction` | Task stem, for example `antonyms` or `sentiment` | [Instruction Induction](https://github.com/orhonovich/instruction-induction) | A separate LLM semantic-equivalence call, with a requested counterexample |
| `ilp` | All 19 synthetic author configuration IDs | [HRI (Glanois et al., 2022)](https://proceedings.mlr.press/v162/glanois22a.html) | cvc5 finite Horn least-model encoding with independently replayed CE |
| `scan` | `simple`, `length`, `addprim_jump`, `addprim_turn_left`, or `template_*` | [SCAN](https://github.com/brendenlake/SCAN), standard splits and full `tasks.txt` | Exhaustive enumeration of all 20,910 public commands |

The SCAN repository attributes the benchmark to Lake and Baroni (2018). The paper *Human few-shot learning of compositional instructions* studies related compositional instruction learning, but its human experiment is a distinct dataset.

## Run

```bash
python train_icl_gen.py --task_type cryptography --benchmark_id caesar:0 --mkey gpt5 --use_ce
python train_icl_gen.py --task_type list_functions --benchmark_id c170 --mkey gpt5 --use_ce
python train_icl_gen.py --task_type instruction_induction --benchmark_id antonyms --mkey gpt5 --use_ce
python train_icl_gen.py --task_type scan --benchmark_id simple --mkey gpt5 --use_ce
```

Omit `--use_ce` for the LLM baseline. `baseline.py` also forwards these four task types to that no-counterexample path:

```bash
python baseline.py --task_type list_functions --benchmark_id c170 --mkey gpt5
```

For direct input/output ICL, use `train_icl.py` with the same `--task_type` and `--benchmark_id`. Add `--use_ce` for mistake-driven counterexample selection from the benchmark's labeled training examples. See [`benchmarks/README.md`](../benchmarks/README.md) for commands.

`--rerun`, `--retries`, `--seed`, `--start_size`, `--scale_factor`, `--tot_train_size`, `--eval_size`, `--ce_epochs`, `--ce_start_size`, and `--ce_batch_size` work with these tasks. `--use_reg` adds a concision constraint to the prompt. Results are saved under `logs/opt_prompt/icl_gen_<task_type>/model=<mkey>/ce|std/reg|noreg/<benchmark_id>.json`.

With `train_icl_gen.py --use_ce`, the first epoch takes up to `--ce_start_size` published examples (default 8). Later epochs request up to `--ce_batch_size` counterexamples (default 8 for these four benchmarks; regex remains 128). The actual count may be zero. Paper-style Cryptography can return single-letter or complete-string witnesses from its bounded SMT search; List Functions and SCAN can return multiple witnesses up to the requested limit; Instruction Induction asks the LLM for up to that limit in one call. Direct `train_icl.py --use_ce` instead adds model mistakes from each scheduled batch of the published training pool, capped at `--ce_batch_size` (default 8) per epoch.

## Oracle limits

List-function equivalence for arbitrary Python is undecidable. Its cvc5 sequence query searches symbolic integer lists of length 3–8, with values 0–100, when both functions fit the supported expression subset. Otherwise it evaluates the functions on the published examples and generated lists, then uses cvc5 to select disagreements. A completed nonempty search with no witness returns `Equivalent: true` as a noisy, operational acceptance criterion and ends the current std/CE run. This is not a global proof for arbitrary Python. `OracleDetails` records the search scope and heuristic policy. Unsupported SMT translations fall back to concrete search; solver errors/unknown results or an empty concrete search remain `null` unless a counterexample is found (`false`).

Instruction Induction's LLM oracle is heuristic. It requests up to `--ce_batch_size` distinct counterexamples in one call and verifies claimed labels when an input appears in the published data. Novel-input claims and equivalence verdicts may still be wrong; the logs retain the oracle response. No exact execution accuracy is reported for that task because the benchmark has no executable reference function.

List Functions and SCAN candidates execute standard Python with a 10-second per-input timeout. Their executors are not security sandboxes. SCAN evaluation uses the full selected split test set; its exhaustive oracle covers all public commands, including held-out test commands.

The two SMT oracles use the `cvc5` Python API installed by `requirements.txt`. No separate `cvc5` command-line program is required. Solver queries have a 10-second per-check time limit.

## Cryptography task protocol update

Default Cryptography generation uses the author's blind `fn(x)` Python-program interface rather than JSON cipher classification. It uses 10 observed examples with clean labels only (optional correctly labeled OOD replacements) and 10 test examples by default. See [the benchmark README](../benchmarks/README.md#cryptography-original-paper-task-protocol) for flags, scope, output naming, and differences between the shared CE method and the original paper's methods. SMT acceptance covers only ASCII-letter strings of length 0–10; unsupported programs and solver unknown remain inconclusive. Old closed-JSON logs retain their historical setting.


Current native coverage: Instruction Induction 24 task types (67,662 induce and 2,156 execute IO); SCAN all 104 official paired splits; ILP all 19 synthetic author configurations. Difficulty annotations and exact IDs are in datasets/benchmarks/difficulty_catalog.json; per-task coverage is in analysis/benchmark_difficulty/native_dataset_coverage_zh.md. Native SCAN files can be restored with `python datasets/scan/prepare.py` using the pinned source manifest. Default benchmark evaluation loads full test IO; explicit positive --eval_size limits supported tasks. Training pools remain full, while per-run scheduling defaults to 384 and supports --tot_train_size 0 for the full pool.
