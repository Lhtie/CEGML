最新版的共同主干与可选分支图见 [analysis_activity_diagram.md](analysis_activity_diagram.md)。该图对应重新逐 call 扫描的 full-pipeline 范围；完整记录清单见 [full_pipeline_call_audit.csv](full_pipeline_call_audit.csv)。

本版只关注同时启用 reflection 和 repair loop 的 full pipeline，分析对象是 Response 中实际保存的 analysis 文本，不再把最终 `<reasoning>` 摘要或外部程序操作当作模型 analysis 的内容。

**范围。** 主体语料为两个原始 scaleup 目录中的 `agentic_reflection` 配置，包括 reg/noreg 及反例生成策略变体。原始全量提取中，540 个 GPT-OSS 文件保存了 9,094 段 analysis，其中 4,746 段位于 retry index > 0。GPT‑5.4 和 Qwen 对应记录未暴露可比的 analysis，因此不依据其最终摘要推断 analysis 行为。另程序检查了 102 个在 prompt 中同时实际出现跨轮 reflection 和 retry repair feedback 的 `agentic_no_clustered` 文件；其 2,005 段 analysis 不计入上述主体统计。

下述内容来自全文提取、检索及代表性完整片段细读，不是逐条语义标注，也没有测量各类活动的 token 占比。具体出处、run/epoch/call 和 analysis 摘录见 [full_pipeline_evidence.json](full_pipeline_evidence.json)，英文详版见 [summary_en.md](summary_en.md)。E1–E9 是证据文件中的编号。

**实际可观察到的活动有八类，不能视为每次都会按顺序完成的八个步骤。**

1. **重列与重新表示样本。** 把正负例再列一遍，数长度、分重复块、识别前后缀，将原始串改写成“若干 b + 若干 ca”等描述。即使已有上一轮假设，repair 响应也可能从重列整个数据开始。这里的计数和分块有时会出错，随后影响规则猜测。

2. **提出多个解释，拿个别样本排除。** 模型会考虑长度、字符类别、子串、位置、次数等解释，再指出某个正例不满足某条件，因此排除该条件。E3 中，它依次检查结尾限制、ion 周围字符、大小写、数字、ion 前后是否必须有字符等，最后采用“含 ion 且不含 old”。这是文本中可见的假设比较，不能据此认定模型系统搜索了全部候选。

3. **结合新样本重审旧规则。** 有些片段明确说新反例使旧解释不足，例如新负例含 ion，说明仅要求含 ion 不够。有些则直接对累计样本重新归纳，几乎不讨论旧解释。E2 在加入空串正例后重新列举数据，确认 c* 包含空串，得到 b + c*。因此，配置启用 reflection 不等于每段 analysis 都显式反思上一轮 reasoning。

4. **解释 repair 反馈，有时只讨论而不修改。** 模型会问为什么得分低、哪些样本应当被接受，并猜测大小写、补集语义、解析器或括号是否有问题。E6 的 ion/old 任务在收到训练准确率 0.465 和修复样本后，仍认定原 regex 正确，输出与前一次相同的候选。下一个 retry 才去掉运算符附近的空格，日志结果随后变为训练准确率 1 且等价（E7）。这是已记录的表达式和结果变化；analysis 中关于引擎的猜测不能当作已验证的故障原因。

5. **处理符号语法与最终输出格式。** 内容包括把“一次以上”转成 c c*、选择交与补运算、检查括号和空格、估算长度，以及准备 `<ans>` 和简短解释。E1、E3、E7 都有这类段落。这部分占用 analysis 文本，但不一定改变语言假设。

6. **判断字符类样本的含义。** ExtRX 中模型有时反复纠结 `[a-z]` 是字面文本还是字符集合。E8 起初把 B7[0-57-9] 当成带方括号的字符串，再读题后改为字符类解释。误把含括号负例视为“超出 alphabet，因此自动拒绝”，会绕过该反例真正表达的约束；但不能假定所有纠结都得到正确解决。

7. **心算验例、发现错误，也会产生错误。** E4 将负例 bcacacacacac 错分成完整 ca 块，继而猜测 ca 次数上界和 b 数量模 3 的条件。该串实际上有一个落单的结尾 c。E5 在后续 retry 反复计数，终于发现这个末尾 c，再检查简单规则 b* (c a)*，最终候选等价。这个案例直接支持“样本解析错误及其修正”的描述；笼统归因为旧解释锚定会遗漏可见的具体错误。

8. **重复已有内容，未必产生新推断。** E9 大量重复同一个长正例，该记录没有提取到 prediction。其他片段也会反复说 regex 应当正确，或重复验同一例子。能观察到的是重复生成和该记录未产生可提取候选；不能只凭文本断言终止原因，也不能把更长 analysis 直接等同于更多有效推理。

这些 analysis 同时包含样本整理、规则搜索、反馈讨论、符号表达、心算检查和输出规划，也包含误读、猜测和重复。reflection 与 repair 提供的信息有时被明确使用，有时没有带来可见的诊断或候选修改。编译、计算得分、等价检查和生成反例由外部程序执行，不属于模型在 analysis 中实际完成的操作。
